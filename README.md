## 先定分支，再定机器

SteamCMD 默认拉的是稳定分支，命令就是 `app_update 380870 validate`。想跟 Build 42，得额外指定测试分支：`app_update 380870 -beta unstable validate`。

这一步要放在选机器之前，因为它直接决定内存预算和模组数量。

B42 引入了多线程渲染和不少机制重做，模组生态还在追，版本更新也频繁。长期服更稳的做法是留在 B41，另开一台机器或另一个安装目录跑测试服，两边的存档互不覆盖。测试服崩了，主世界还在。

版本之间还有一层硬限制：B41 和 B42 的模组不通用。切版本之后原来的模组列表要重新整理，模组一多，内存和硬盘的余量也得跟着加。

## 配置怎么算

服务端本体是 Java 应用，`start-server.sh` 背后拉起的是 JVM。你给机器配 8GB，不等于 8GB 全归服务端用，堆上限由 `-Xmx` 参数决定，堆之外还有原生内存和系统进程。

内存配多少，两套口径可以对着看。

第一套按人数给下限，以 B41 纯净版为基准。2 到 5 人配 2 核 4GB，6 到 10 人配 4 核 8GB，10 到 16 人配 6 核 12 到 16GB，模组多再往上加。

第二套把系统和非堆内存的余量算了进去。有托管商在自己的实战笔记里给出的经验是给机器留约 3GB 非堆余量，10GB 的机器把堆设成 7GB 左右。按这个思路，2 到 4 人原版或少量模组就该从 4 核 8G 起步，4 到 10 人带中等模组量走 4 核 8G 到 6 核 12G，10 人以上或大模组社区服奔着 6 核 12G 以上去。

| 人数与模组量 | 按 B41 纯净版给的下限 | 算了非堆余量的起点 |
| --- | --- | --- |
| 2–5 人，原版或少量模组 | 2 核 4GB | 4 核 8GB |
| 6–10 人，中等模组量 | 4 核 8GB | 4 核 8GB 到 6 核 12GB |
| 10 人以上或大模组 | 6 核 12–16GB | 6 核 12GB 以上，考虑独立 IP |

两套数字差得不小，差额就出在非堆余量和模组量上。按你实际要装的模组数量取中间值，比套用「每人多少 MB」的经验公式靠谱。

CPU 看单核。玩家移动和僵尸 AI 的判定、区块加载都压在服务端主线程上，多核有收益但不线性。这也是高主频型号比同价位多核型号更适合 PZ 的原因。

带宽看上行。家用宽带下行几百兆、上行只有几十兆，人一多就开始掉包跳 ping。10M 上行对十来个人的 PZ 服不算紧张，线路稳定性和延迟的影响更大。

硬盘要留冗余。服务端文件本身不大，但创意工坊模组、地图和存档会持续增长，日志也会堆积。机械盘换成 SSD，存档写入和地图加载的改善是能直接感觉到的。

## 从零开始的搭建流程

1. 买一台 64 位 Linux 机器，硬盘选 SSD。

2. 建一个普通用户跑服务端。程序装在 `/opt/pzserver` 这类目录，不要长期用 root 运行游戏进程。

3. 装 SteamCMD，进入后依次执行：


force_install_dir /opt/pzserver
app_update 380870 validate
quit


380870 是 Project Zomboid Dedicated Server 的应用 ID。服务端免费、匿名登录下载，不需要买第二份游戏。安装目录要保证运行用户有读写权限。

4. 第一次启动，顺手设管理员密码：

`./start-server.sh -servername MyPZServer -adminpassword '换一个足够长的密码'`

首次启动会生成世界和一批配置文件，要等一会儿。控制台出现 `SERVER STARTED` 才算真的起来了。服务器名会进入多个文件名和存档路径，上线之后别随便改，否则看起来像开了个新世界。

5. 配置文件和存档不在安装目录里，而在运行用户的家目录下。配置是 `~/Zomboid/Server/servertest.ini`，世界在 `~/Zomboid/Saves/Multiplayer/servertest/`。名字里的 `servertest` 只是默认档名，不是测试模式。

6. 改 `servertest.ini`，先动服务器名、玩家上限和访问密码这几项基础设置，再决定是否公开列表、是否开 PVP，最后填模组那两行。改之前把整个目录复制一份到服务器以外。

7. 开端口。16261/UDP 是主端口，负责服务器列表、握手和玩家直连时输入的那个端口；16262/UDP 是握手之后的数据端口；27015/TCP 供 RCON 远程管理使用，可选。老教程里写的 8766 到 8767/UDP 是早期版本做 Steam 查询用的，现在多数场景已经不需要。

8. 开防火墙时别忘了云控制台的安全组。系统防火墙和云平台安全组是两套东西，只开一边等于没开。UDP 16261 和 16262 必须都放行。

9. 上模组。`Mods=` 和 `WorkshopItems=` 两行都要填，用分号分隔，少填一行客户端就加载不出来。带模组的服如果玩家被反复踢出，先去服务端日志里对照反作弊相关设置，多半是那里跟模组冲突。

10. 停服在控制台输入 `quit`，让它走完保存流程。直接 kill 进程是存档损坏的常见起因。用 systemd 管进程的话要注意，如果配置里写了自动重启，手动 `quit` 会被当成异常退出，十几秒后服务端又自己起来，看着像是关不掉。正常停服应该用 `systemctl stop`。

11. 定时把配置目录和存档目录打包，存到服务器以外的地方。服务器本身也能做快照，但别把唯一备份留在同一台机器上。

Windows 也能跑服务端，要求 Windows 10 1803 或更高版本。装好之后不要通过 Steam 启动专用服务器，这个坑官方教程连强调了三遍。Windows 系统本身占的内存比 Linux 多，同样配置能带的人会少一些。

## 连不上服务器，按这三步查

先看 16262 有没有放行。只开 16261 是最常见的错误，典型症状就是玩家能看到服务器，加入时超时，或者连上了卡在加载画面。

再看安全组和系统防火墙是不是只配了一边。

最后确认本地网络是不是在 CGNAT 后面。路由器的 WAN 口 IP 和真实公网 IP 对不上时，端口转发做多少遍都不会生效，这条路只能换成有独立公网 IP 的机器。用手机流量做一次外网测试，比在局域网里反复试快得多。

## 家用电脑开服和租云服务器，差别在哪

在家里用旧笔记本开服是可行的，成本也低。需要接受四条限制：运营商 CGNAT 会让端口转发失效，国内家用宽带的公网 IP 会变，上行带宽小，机器得 24 小时开着，电费和噪音自己承担。

四个人以内、都在同一个城市、玩的时间不固定，家里开就行。人再多一点，或者需要固定 IP 让朋友随时能连、不想让游戏进程占着自己的电脑，租一台机器更省事，代价是每月一笔支出。
